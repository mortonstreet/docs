The **Credentials** page (`/settings/admin/credentials`) has two halves: the capabilities
Revcenter runs for you, and the third-party tools you connect with your own account.

## Included with Revcenter

These run on the launched RevCenter API. There's nothing to configure and no vendor key
to manage — usage draws down your workspace's credits.

| Capability | What it does |
|---|---|
| Web search | Finds candidate and company profiles across the open web |
| LinkedIn enrichment | Full profile and company data behind every qualified match |
| AI scoring | Reads your prompt into criteria, then scores and ranks every match |
| Platform storage | Database, storage, and realtime updates |

The public API is available at `https://api.revcenter.ai/v1` for customer software,
agents, MCP wrappers, and direct HTTP clients. See [RevCenter API v1](/guides/revcenter-api-v1)
for bearer-token auth, scopes, rate limits, and examples.

Each integration shows its status:

- **`connected`** — an active key is stored, encrypted, for your workspace.
- **`not connected`** — nothing saved. Features that need it say so rather than silently
  degrading.

## Adding or rotating a key

Click **Add key**, paste the key, and save. Rotating doesn't overwrite the old key — the
previous one is deactivated (`is_active = false`, `retired_at` set) and a new row is
inserted, so there's an audit trail of every key that was ever active.

**Deactivate** requires a confirm click (the button becomes Confirm / Cancel) before it
takes effect — no accidental one-click removal of a working key.

## Credits

Everything under *Included with Revcenter* is metered in credits, shown on
**Settings → General**. The balance is expressed as the work it covers rather than a bare
number, so you can see what's left in searches, enrichments, and scoring instead of
guessing.

Two things worth knowing:

- **Integrations never consume credits.** You already pay Prospeo, HeyReach, and SmartLead
  directly; charging credits on top would bill you twice.
- **A search that runs out mid-flight finishes its current stage before stopping.** You
  get a complete, scored result set — smaller than you asked for, with a note explaining
  why — rather than profiles found but left un-enriched.

## How this stays secure

- Keys are encrypted with **AES-256-GCM** before they ever touch the database, using a
  server-only `CREDENTIAL_ENCRYPTION_KEY`.
- The browser never receives a key back in plaintext — only a masked hint like
  `px_test_••••2345`, generated at save time and never re-derivable from the stored
  ciphertext.
- Decryption happens exclusively in server-side code, which resolves your workspace's own
  key and never shares it across workspaces.
- Every credential is scoped to your organization, and the lookup always goes through your
  current session.
